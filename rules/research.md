# Research rules

The failure this prevents: a decision built on a remembered API, a vendor claim nobody
checked, or a benchmark with no source.

- **Library and tool documentation: a docs tool first** (Context7 or equivalent), not
  memory. **Code examples and outside benchmarks:** a code search tool. **Prices,
  limits, availability and anything recent:** fetch the vendor's own page and date it.
- Primary sources over summaries: the vendor's documentation, the repository, the issue
  tracker, the standard or the law. A blog post is a lead, not a source.
- Mark every claim: **[V]** verified against the cited source in this session, **[I]**
  inferred. A note without the markers is not finished.
- Date every check ("checked 2026-10-08"). End with an evidence log naming the tools used
  and the sources, with URLs.
- Decisions the project has already recorded are not reopened by research. A note that
  argues against one says so in a clearly labelled section the owner can find.
- Never copy customer or business data from another repository — structure and practice
  only. Never read an environment file.
- A research note proposes; the owner decides. End with the decisions still open, grouped,
  recommendation first.
